## Architecture

### End-to-End Flow

```
User: "Train a model on genetic data"
    ↓
🐿️  SQUIRREL: AI Interpretation
    "I understand: ML training, distributed, encrypted, checkpointed"
    ↓
🎵 SONGBIRD: Service Discovery & Orchestration
    "Found 2 GPU towers: eastgate (RTX 2070), northgate (RTX 5090)"
    ↓
🐻 BEARDOG: Encrypted Data Access
    "Encrypted data ready (AES-256-GCM), access granted for 60min"
    ↓
🍄 TOADSTOOL: Distributed GPU Training
    "Training across 2 GPUs... Complete! Accuracy: 97.4%"
    ↓
🏠 NESTGATE: Persistent Storage
    "Model v1.0.0 saved, ZFS snapshot created"
    ↓
Result: "✅ Model ready! ID: model_v1_0_0, Accuracy: 97.4%"
```

### Primal Responsibilities

| Primal | Role | Contribution |
|--------|------|-------------|
| 🐿️  Squirrel | AI & Intent | Interprets natural language, predicts optimal routing |
| 🎵 Songbird | Orchestration | Discovers services, coordinates across towers |
| 🐻 BearDog | Security | Provides encrypted data access, key management |
| 🍄 ToadStool | Compute | Executes distributed GPU training |
| 🏠 NestGate | Storage | Persists results, snapshots, versioning |

## Key Concepts

### 1. Natural Language Interface

**User says**: "Train a model on genetic data"

**Squirrel interprets**:
- Task type: ML training
- Dataset: genetic_sequences
- Requirements: GPUs, encryption, checkpointing

**Result**: Structured task definition

### 2. Capability-Based Discovery

**No hardcoded service names!**

```rust
// ToadStool discovers what it needs:
let ai_service = discover_service_by_capability("ai-inference")?;
let orchestration = discover_service_by_capability("orchestration")?;
let security = discover_service_by_capability("encryption")?;
let storage = discover_service_by_capability("persistent-storage")?;
```

### 3. Seamless Coordination

Each primal:
- Knows only itself
- Discovers others by capability
- Contributes its expertise
- Passes results to next stage

**Result**: Decoupled, resilient, scalable system

### 4. Production-Ready Output

Not just a demo - this pipeline produces:
- ✅ Trained model (97%+ accuracy)
- ✅ Encrypted throughout
- ✅ Distributed for speed
- ✅ Checkpointed for resilience
- ✅ Versioned for production
- ✅ Snapshotted for rollback

## System Benefits

### 1. Unified Interface

**One command** → **Full pipeline**

No manual:
- Service discovery
- Resource allocation
- Security configuration
- Storage setup
- Result retrieval

### 2. Automatic Optimization

Each primal optimizes its domain:
- Squirrel: Best routing strategy
- Songbird: Optimal tower selection
- BearDog: Appropriate encryption level
- ToadStool: GPU vs CPU vs Neuromorphic
- NestGate: Deduplication & compression

### 3. Fault Tolerance

Any primal can fail:
- Squirrel → Rule-based fallback
- Songbird → Direct tower connection
- BearDog → Unencrypted mode (dev only)
- ToadStool → CPU fallback
- NestGate → Local storage

**System continues operating!**

### 4. Scalability

Add more of any primal:
- More Squirrel instances → Higher throughput
- More Songbird nodes → Larger mesh
- More ToadStool towers → More compute
- More NestGate nodes → More storage

**Linear scaling!**
