## 🎯 Report Guidelines

### When to Create a Report

Create a new report when:
1. Completing a major development session
2. Reaching a significant milestone
3. Making important architectural decisions
4. Conducting technical analysis or audits
5. Preparing for production deployment

### Report Structure

All reports should include:
1. **Title and Metadata** - Date, status, purpose
2. **Executive Summary** - Key points (2-3 paragraphs)
3. **Details** - Main content
4. **Conclusions** - Findings, recommendations
5. **Next Steps** - Action items

### Report Naming

Use this naming convention:
- Status reports: `STATUS.md`, `DEPLOYMENT_READY.md`
- Session reports: `SESSION_COMPLETE_<DATE>.md`
- Technical reports: `<TOPIC>_REPORT_<DATE>.md`
- Archived reports: Move to `docs/archive/<date>/`
